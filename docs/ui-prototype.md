# Web 页面原型：设计与交互约定

日期：2026-10-15。本轮只做页面原型：数据来自本地生成的演示数据和占位图，不访问任何 RSS 服务；数据层（core-ts 模型、Miniflux 适配器、IndexedDB、同步队列）留到下一轮。本文记录已经和用户确认的方向与原型里的具体做法。

## 已确认的方向

| 项目 | 决定 |
| --- | --- |
| 视觉基调 | 浅色内容社区：白底、圆角卡片，接近小红书 / Pinterest；深色作为可选主题 |
| 卡片文字 | 图 + 一行作者信息（订阅图标、作者、分类）。标题只在悬停和查看器里出现；实测推文标题常与图无关 |
| 卡片操作 | 作者行右侧放“下载”，即存入设备（不是离线缓存） |
| 下载能力 | 图源允许网页读取时一键下载；不允许时引导用户右键 / 长按图片保存，或打开原图。不为此修改 RSS 服务的代理或跨域配置 |
| 图集查看 | 沉浸查看器：深色全屏、左右翻页、缩放、缩略图条，文章信息按需展开 |
| 连续浏览 | 看完当前图集继续翻页，直接进入列表里的下一组；向前翻同理进入上一组的最后一张。不做定时自动播放 |
| 分类 | 只显示 RSS 服务里的分类（Miniflux 每个订阅一个分类），不做“常看”等客户端分组。作者旁边显示订阅的分类，不再按地址关键词猜测平台；账号里少于两个分类时，分类筛选和作者旁的分类都不显示 |
| 已读与位置 | 未读列表里看过的图集保留并变暗，直到同步或改筛选条件；关闭查看器停在最后看的那组 |
| 本轮范围 | 只做页面原型，iOS 与 Swift 只建目录（本机为 Windows，无 Xcode） |

## 视觉系统

材质概念是“白纸、墨、网点”：界面只用灰阶，把色彩留给插画。

- 颜色变量在 `apps/web/src/styles/tokens.css`。墨色 `#16161a` 用于正文与主要按钮；唯一的彩色是印刷品红 `#e5007e`，只标记“属于你”的状态：收藏星标、新内容提示、标志里的一格。深色主题由同一组变量切换，查看器始终是深色。
- 网点（`components/tone`）是所有“还不是一张图”的状态的统一材质：加载中、尺寸未知、加载失败、没有图片、图片待解析、骨架屏。加载中时网点缓慢移动。
- 字体：Latin 与数字用 Mona Sans（随应用打包的可变字体，不从第三方加载），中日文交给系统字体。标志与计数使用加宽字形。
- 图标：Phosphor，当前页签用实心，其余用线框。

## 页面与路由

| 地址 | 页面 |
| --- | --- |
| `/connect` | 连接服务：Miniflux（API 密钥）或 Google Reader 兼容（用户名、密码），可选“记住登录”；也可以进入演示数据 |
| `/` | 浏览：未读 / 全部、图集 / 图片流、按分类筛选；筛选条件都在地址参数里 |
| `/starred` | 收藏 |
| `/feeds` | 订阅：按分类分组的画师卡片（最近三张封面、未读数、抓取错误）。数据模型允许多对多，以兼容支持多个标签的 Google Reader 服务 |
| `/feeds/:id` | 单个订阅：刷新、全部标为已读（可撤销）、抓取错误横幅 |
| `/settings` | 账号、浏览、外观、图片缓存；演示模式下另有原型调试项 |
| 任意列表页加 `?view=文章&i=序号` | 查看器 |

桌面端（≥900px）左侧导航含四个入口和画师列表；窄屏用底部四个页签。

## 瀑布流

- 列数按容器宽度和“卡片大小”设置计算；窄屏固定为三 / 二 / 一列。
- 长图（高宽比 > 1.8）限高、从顶部裁切、底边渐隐并标“长图”；很宽的图最多压到 2:1。
- 角标都在图片右上角：张数（或图片流里的序号）在最右，“长图”在它左边，卡片太窄时换行；左上角是收藏星标，底部留给悬停时的标题。
- 先测量再入列：绝大多数图片没有宽高（本地实测 167 张里只有 6 张有），卡片拿到尺寸后才放进布局，放下后不再移动。在第一张未放下的卡片之后的窗口（三行）内，谁先测量完谁先放，慢图不会挡住整面墙；等待超过 3 秒的按 4:3 放置，图片到达后在框内裁切。
- 只渲染视口附近的卡片；接近底部时测量后面几行、追加下一页。
- 列表是快照：在查看器里标为已读或取消收藏的文章不会立刻消失，只是变暗；显式同步或改筛选条件后才重新取数，列表不会因此跳动。
- 后台同步（回到前台时）只提示“有 N 个新图集”，点了才放进列表；手动同步直接刷新列表。

## 查看器

- 地址带 `?view=&i=`：打开时压入一条历史，翻页替换当前这条，浏览器返回键即关闭。
- 打开和关闭时卡片与大图之间有放大 / 缩回过渡（View Transitions，浏览器不支持或开启“减少动态效果”时直接切换）。
- 翻页顺序取自打开它的列表。到达图集边缘时，左右箭头变成带头像的“上一组 / 下一组”，缩略图条末尾也有下一组的入口，进入相邻图集时顶部短暂提示作者和张数。
- 背后的列表跟随滚动，关闭时停在最后看的那张卡片上，焦点也回到这张卡片。
- 至少一张图片显示成功后标为已读（设置里可关闭）；滚动列表和预加载不会标记。
- 操作：收藏（S）、下载当前图片、文章信息（I）、更多（打开原图、查看原文、复制图片地址、分享、标为未读 / 已读）。键盘 ←/→ 翻页、Esc 先复位缩放再关闭、+/-/0 缩放。
- 缩放：滚轮、双击、双指；放大后拖动平移。长图双击直接放大到撑满宽度、从顶部开始。触屏左右滑动翻页、下滑关闭、单击隐藏界面。鼠标静止约 2.6 秒后界面自动隐藏。
- 文章信息在桌面端是右侧面板（记住开关状态），窄屏是底部弹层（每次从收起开始）。窄屏的操作按钮在底部一行。

## 下载与能力边界

下载即存入设备，按资源实际可读性给出结果：

- 浏览器允许页面显示跨域图片，但只有图片服务器返回 CORS 允许头时，脚本才能读到图片数据并存成文件；跨域地址上的 `download` 属性也会被忽略。本地实测图片都能用 `img` 显示，脚本读取全部失败（见 [本地连接验证](local-connectivity.md)）。用户自己右键或长按保存不受这个限制。
- 可读：直接保存。图集逐张保存还是打包，接真实数据时再定。
- 不可读：提示“来源不允许网页直接下载”，说明右键（手机上长按）图片即可保存。卡片上的提示操作是“在查看器中打开”，查看器里是“打开原图”。查看器不拦截图片的右键菜单和长按菜单，长按也不会被当作单击。
- 原型里 Bilibili 的图片按“不可读”处理，用来展示这个分支。
- 已决定不修改服务端配置。若以后要让所有图片都能一键下载，可在 Miniflux 设置 `MEDIA_PROXY_MODE=all`，并给 `/proxy/` 加 CORS 允许头（或与 Miniflux 同源部署）。当前 Miniflux 使用默认的 `http-only`，代理响应不带 CORS 头。

## 只属于原型的行为

- 演示数据与占位插画在本地按种子生成（`apps/web/src/prototype`），画师名和链接都是虚构的，链接指向 example.com。
- 设置 → 原型调试：模拟图片加载耗时（默认开）、模拟后台同步、重置演示数据。
- 连接页不发出请求；服务地址里含 `fail` 时演示连接失败。未勾选“记住登录”时，刷新页面会回到连接页，与第 7 节的凭据策略一致。
- 下载不写入文件，只演示进度与结果。
